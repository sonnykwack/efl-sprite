# 개발 과정 기록

곽태훈 (단국대학교 소프트웨어학과, 32210214)

이 문서는 **어떤 판단으로 무엇을 바꿔 왔는지**를 날짜순으로 기록합니다. 구현은 AI 코딩 도구
(Anthropic Claude Code)를 활용했고, 기획·요구사항·채점 기준·검증·테스트·배포는 제가 맡았습니다
(역할 분담은 [README](../README.md#2-개발-과정과-역할-분담) 참고). 채점 실험의 수치는
[`scoring-experiments.md`](scoring-experiments.md)에 있습니다.

## 개발 방식

```
① 요구사항·기준 정의 (나)  →  ② 구현 (AI 코딩 도구 활용)  →  ③ 실기기 실행·채점 비교 (나)
        ↑                                                         │
        └──────── ④ 문제 발견과 개선 방향 제시 (나) ←───────────────┘
```

- 매 반복마다 제 Mac에서 앱을 실행하고, 같은 답안을 강사로서 직접 채점한 점수와 비교했습니다.
- 모든 변경은 GitHub에 올리는 즉시 macOS·Windows에서 자동 빌드되어 두 OS 호환성이 유지됐습니다.

## 날짜별 주요 결정

### 주제 선정과 방향
- 스토어 배포까지 가능한 주제를 찾다가, 학원에서 TOEFL을 가르치며 느낀 **말하기·쓰기 피드백 병목**을 주제로 정했습니다.
- 범위를 **스피킹·라이팅**으로 좁히고, 학생 데이터가 외부로 나가지 않는 **온디바이스 AI**, 배포처는 **Microsoft Store**, 개발은 Mac·배포는 Windows로 정했습니다.
- Microsoft Partner Center 개발자 계정을 등록하고, 상표 문제를 피해 앱 이름을 **EFL Sprite**로 정했습니다.
- 기준 답안(Academic Discussion)을 직접 채점했습니다: **밴드 3.0–3.5**. 근거로 *Because* 조각문, *many of us was* 수일치, *so* 대신 *therefore/thus*, *thing*·*some* 같은 모호한 어휘, 소유격 누락, 이유의 깊이 부족을 짚었습니다. 이 7개 항목이 이후 채점 개선의 기준이 됐습니다.

### 4개 유형과 첫 채점 비교
- TOEFL iBT 2026의 **4개 유형**(Listen and Repeat, Interview, Email, Academic Discussion)으로 가기로 결정했습니다.
- "채점하려면 무엇을 채점하는지 보여야 한다"는 문제를 지적해, 문제와 답안이 함께 보이는 채점 화면으로 바꿨습니다.
- 초기 AI가 제가 짚은 항목 대부분을 놓치는 것을 확인했고, 그 결과 규칙 검사와 인용 스냅이 도입됐습니다. 이후 5개 항목을 모두 검출했습니다.
- 평가용 답안 세트(ES-1)를 만들었습니다. 수준과 넣을 오류 유형은 제가 정했고, 초안은 AI 도구로 작성했습니다. 채점은 앱 결과를 보기 전에 블라인드로 했습니다.

### "점수가 너무 후하다"
- ES-1 1차 결과에서 **55단어짜리 명령조 이메일이 4.0**을 받은 것을 지적했습니다. 그 결과 보정 앵커, 분량·어조·오류 밀도 상한, 밴드 환산표 재조정이 들어가 같은 답안이 **2.5**가 됐습니다.
- "밑줄에 마우스를 올려도 고친 표현이 안 보이고 이유가 없다"고 지적했습니다(macOS 웹뷰는 툴팁이 뜨지 않음). 그래서 **클릭형 교정 카드**와 오류 분류별 문법 원칙 설명이 생겼습니다.
- "모델의 문법 전문성을 높일 방법은 없나 — 전문 문법 모델이 있어야 할 것 같다"는 판단에 따라, 학습자 영어 전용 교정 모델 **GECToR**를 도입했습니다(Rust + ONNX Runtime 포팅). 그 뒤 제가 넣은 오류 7/7을 검출했습니다.

### 피드백 품질
- "피드백이 부자연스럽다 — *반응*이라는 말, 한자가 그대로 나온다"고 지적했습니다. 그 결과 **한국어 번역 검증 체계**(문자 집합 제약, 문장 단위 번역, 용어집, 실패 시 영어 원문)가 생겼습니다.
- "모델이 문제의 조건을 제대로 이해하지 못하고, 에세이에 조건이 들어 있는지 분간하지 못한다"고 지적했습니다. 그래서 **요구사항별 개별 판정**(근거 문장을 먼저 인용한 뒤 판정)으로 바꿨습니다.
- "맞는 에세이에 문법 포인트가 엉망으로 붙는다"고 지적했습니다. 그래서 **정확도 우선 구조**(문법은 문법 모델과 규칙만 판단, LLM 교정은 별도 호출로 재검증)로 바꿨습니다.
- 접속사 위치가 엉뚱한 단어에 표시되는 문제, 문법 모델이 시제를 두 번 바꾸는 문제를 발견해 수정했습니다.

### 기준의 정직성, 스피킹, 학원 운영 기능
- "내 채점은 ETS 공식 기준이 아니라 강사로서의 주관적 판단"임을 밝혔습니다. 그에 따라 보고서의 주장을 **"현직 강사 판단과의 일치도"**로 한정하고, 최종 검증은 ETS 기준표와 2인 채점으로 하기로 했습니다. 채점 조정은 이 시점에서 동결했습니다.
- 스피킹 녹음을 실기기에서 테스트했습니다.
  - "시작"이 반응하지 않는 문제를 개발자 도구 로그로 추적했습니다(원인: 화면 재마운트 시 상태 초기화 누락).
  - 무응답 녹음 같은 경계값도 확인했습니다.
- 학원 운영에 필요한 기능 3가지를 요구사항으로 정의했습니다.
  1. **문제 공급**: 조교가 만든 문제 파일을 학생이 **카카오톡·USB로 받아 로컬에서 가져오기** + 로컬 AI 문제 생성
  2. **채점 세분화**: 분량·맥락·어휘 등 루브릭을 더 세분화. 그 결과 코드로 재는 언어 지표 5종과, 지표와 AI 판단의 일관성 검사가 들어갔습니다.
  3. **교사 직접 첨삭**: 왼쪽에 문제·에세이, 오른쪽에서 *드래그 → 오류 유형 드롭다운 → 코멘트 → 수정된 에세이*. AI가 잘못 교정한 부분을 바로잡을 수 있게 했습니다.
- Microsoft Store 패키지 ID(`TaehoonKwack.EFLSprite`)를 발급받아 MSIX 빌드에 반영했습니다.
